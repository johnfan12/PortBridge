# 架构

单一 Go 二进制 hub/node，原生 Azure 风格 HTML/CSS/JS 编译内嵌。hub 保存 bbolt 事务快照，node 配置用临时文件、fsync、rename 原子更新。数据带 portbridge 项目标记，防止误用 NodeBridge 数据。

hub HTTPS 控制台与 `/api/connect` 共享端口，node 主动建立按指纹验证的 TLS/WebSocket 连接，yamux 复用独立流。

- 状态类型 2：node → hub，JSON 带本机名称、授权端口就绪与 TCP 暂停；限 64 KiB、读取 5 秒。
- TCP 类型 3：hub → node，随后 2 字节大端目标端口；node 验证本机允许列表与暂停，连接 127.0.0.1，返回 ACK 0/1 后双向传输。
- 不提供类型 1 的专用 SSH 转发。端口授权不能包含节点维护端口，最多 16 个端口。
- 每代理最多 128 个公网连接，node 最多同时处理 128 个流；保留 TCP 半关闭和大数据背压。

配对仅创建节点身份，单次邀请消费与节点记录在一个事务中；公网端口在管理员创建代理时分配。最多 100 个节点与 100 个服务，端口监听和数据库提交由互斥锁保护，失败回滚。重启恢复同一端口，冲突可重试。

本机撤销、暂停和数据流登记共用锁，避免新连接绕过授权。VPS 暂停关闭单服务活动连接并保留监听，节点暂停关闭其所有服务流。删除节点事务清理所有关联代理并撤销凭证。

首次管理员随机密码本机生成，密码 bcrypt，Cookie Secure/HttpOnly/SameSite=Strict；数据库仅保存会话令牌和节点凭证摘要。管理写接口要求管理员、同源、自定义请求头；节点维护仅回环监听且校验 Host/Origin。普通账号只能查看节点状态，不能管理或列举转发。

HTTP 服务公网端口不受控制台 Cookie 登录保护；由服务自身鉴权。HTTP 客户端到 VPS 为明文，隧道 TLS 加密。域名、反向代理和自动证书尚未集成。
